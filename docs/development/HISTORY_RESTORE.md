# 完整历史恢复

Web、desktop 和 mobile 支持恢复正文、Markdown/富文本格式及附件集合。只有原作者可操作；共享笔记仍只读。标题、标签、笔记本和星标不会被历史恢复覆盖。

## API2

- `POST /api2/note/restoreHistory`：token 客户端。
- `POST /api2/noteContentHistory/restore`：Web 会话客户端。
- 表单参数：`noteId`、稳定 `historyId`、当前 `usn`。响应 `{Ok, Msg}`；成功后客户端通过正常读取/同步更新正文、格式和附件，不直接推进同步游标。
- 历史列表增加 `FilesComplete`。仅当为 true 时允许完整恢复；false/缺失表示旧版本附件集合未知，不能按空集合清空当前附件。旧版本仍可显式恢复正文。
- 完整恢复校验所有原件、笔记归属和 USN 后才写入。找不到文件返回 `historyFileMissing`；旧快照返回 `historyFilesUnknown`；版本变化返回 `conflict`。

## 原件保留

修改正文或删除附件前保存当前版本，包括空正文。新快照保存当时的附件记录及格式；图片关系先按相同正文更新，再生成文件清单。内部附件记录包含磁盘位置，仅用于服务端存储，所有公开历史响应都会剔除该字段。

删除附件会移除活动记录、更新附件数量和 USN，但保留原件。共享用户不能通过活动附件接口读取已删除附件。被历史引用的图片拒绝物理删除。附件原件的保留期是所属笔记的生命周期：可见历史仍最多 20 个版本，内部归档目录随新快照保留；永久删除笔记时清理这些原件。磁盘占用因此可能增加，不能把“删除附件”视为立即释放空间。

服务端使用共享进程锁、USN 条件更新和恢复前快照；写入失败会尝试回滚，保留历史和原件供再次恢复。跨集合写入不是数据库事务，进程崩溃、数据库持续不可用或多实例并发下仍需读取最新状态并从恢复前快照重试，不能保证跨集合原子提交。

## 客户端

Web/desktop 共用界面新增“恢复正文和附件”，保留“恢复到编辑器”。完整恢复后重新读取笔记和附件列表。desktop 对服务端版本要求本地笔记已同步，再请求服务端恢复并同步；本地版本使用 SQLite 事务恢复正文、格式及附件记录。

desktop 数据库升级至 v4，历史新增格式与附件 JSON；旧行保留未知状态。本地删除附件保留原件供历史恢复，恢复后的附件重新进入同步上传流程。缺失本地原件时拒绝完整恢复。

mobile 在线历史菜单提供“恢复正文和附件”；本地 dirty 笔记或未处理的附件上传会阻止操作。离线模式继续支持正文与格式恢复，不冒充完整附件恢复。

修复不能找回升级前已物理删除、且没有备份的文件。旧历史不会自动升级成完整快照。当前测试覆盖校验、编解码、API2 请求、界面、SQLite 迁移及恢复；真实 MongoDB/PostgreSQL 集成测试需要单独配置测试数据库，设备和发布验收不包含在本轮。


服务端账号的本地历史只代表客户端当时已缓存的附件，不能推断未下载的服务端附件不存在，因此这类本地快照保留格式与附件元数据，但不声明完整文件集合。完整恢复使用在线服务端版本；纯本地笔记或尚未同步的新笔记可使用本地完整恢复。desktop v4 另保存 `files_complete` 标记，旧行默认未知。

本轮同时修复 desktop 上传时保留已同步附件、空正文附件上传、编辑器格式上传，以及增量同步对完整附件清单的刷新（含空集合）。下载失败不覆盖本地附件集合，错误文本不能当作附件保存。
